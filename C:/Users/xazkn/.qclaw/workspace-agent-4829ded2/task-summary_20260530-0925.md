# DaniNote 4 个 Bug 修复总结

**时间**: 2026-05-30 09:08–09:25  
**状态**: ✅ 全部修复，打包验证通过

## Bug 1: 增大字号先跳到最小

**根因**: `fontPointSize()` 返回 0 表示"使用默认字体"，但代码直接做 `0 + 2 = 2`，导致字号跳到极小值。

**修复**: 在 `_font_smaller()` 和 `_font_larger()` 中，当 `fontPointSize() == 0` 时，用 `self.content_editor.font().pointSize()`（即 11pt）作为基准值。

## Bug 2: 有序/无序列表第一行数字/项目符号不变 + 无序列表自动缩进

**根因**: `cursor.createList()` 会重置部分字符格式，导致列表标记和文本的字号不一致。无序列表缺少标准缩进设置。

**修复**: 在 `_insert_list()` 中：
1. 创建列表前先保存当前字号
2. 创建列表后用 `setCharFormat` 恢复字号
3. 无序列表显式设置 `setIndent(1)` 保持标准缩进

## Bug 3: 插入图片报错 "QTextImageFormat has no attribute ImageResourceType"

**根因**: PySide6 中 `QTextImageFormat.ImageResourceType` 不存在，应使用 `QTextDocument.ResourceType.ImageResource`（值为 2）。

**修复**: `doc.addResource(QTextImageFormat.ImageResourceType, ...)` → `doc.addResource(QTextDocument.ResourceType.ImageResource, ...)`

## Bug 4: 首页窗口无法拖拽调整大小

**根因**: `nativeEvent` 中 `wintypes.MSG.from_address(message)` 传入的是 PySide6 的 `shiboken6.VoidPtr` 类型，不是 `int`，导致 `from_address()` 抛出异常，整个 nativeEvent 从未生效。

**修复**: `wintypes.MSG.from_address(message)` → `wintypes.MSG.from_address(int(message))`

额外修复：添加了 `WM_NCCALCSIZE` 处理（wParam!=0 时返回 True,0），确保无边框窗口的 WS_THICKFRAME 边框逻辑正确。

## 关键发现

PySide6 的 `nativeEvent` 回调中，`message` 参数类型从 Qt5 的 `int` 变成了 `shiboken6.Shiboken.VoidPtr`，必须用 `int()` 转换后才能传给 ctypes 的 `from_address()`。这是所有基于 nativeEvent 的 Windows 原生 resize 方案在 PySide6 上失效的根因。
